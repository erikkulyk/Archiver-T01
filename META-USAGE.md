# Декларація використання ШІ

Початкову версію коду в цьому репозиторії було згенеровано асистентом Claude (Anthropic) за описом проєкту та методичкою. У середовищі початкової генерації .NET SDK був відсутній, тому тоді код не компілювали й не запускали. Подальші зміни та незалежна перевірка еталонних архівів описані нижче.

Команда має: запустити `dotnet test`, виправити помилки, звірити формат зі специфікацією, вказати тут
конкретні модулі, які кожен учасник перевірив і зрозумів, та додати записи про власні зміни.
Без такої декларації множник M = 0,5 (за вимогами методички).

## Додаткова перевірка та зміни за допомогою ChatGPT (OpenAI)

Під час подальшої ревізії ChatGPT допоміг виправити та доповнити такі частини проєкту:
- `Classifier.cs`: читання класу з колонки `type` у фактичній схемі `file,type,type_name,size`; перевірка міток, відсутніх файлів і сумісності збереженої моделі.
- `Format.cs`: порядок полів payload, нульове reserved-поле, 32-бітний розмір файла та 16-бітний лічильник блоків відповідно до еталонних архівів.
- `BlockCodec.cs`: розріджені таблиці канонічного Гаффмана, лічильник токенів і довжина bitstream.
- `ArchiveService.cs`: правильне представлення порожнього файла одним нульовим RAW-блоком.
- `Program.cs` і тести: контроль порога `F1_min`, перевірка відсутньої моделі та регресійні тести для формату, класифікатора й еталонних архівів.

Для незалежної перевірки еталонних даних було використано Python: перевірено HMAC, розшифровано payload і декодовано блоки для `ref_01`–`ref_06`, включно з трьома томами `ref_06`; відновлені розміри та CRC32 збіглися з JSON-описами викладача. Також перевірено, що негативні приклади `bad_01` і `bad_02` мають помилковий HMAC, `bad_03` обрізаний, `bad_04` має неправильний magic, а `bad_05` містить ненульове reserved-поле.

**Обмеження перевірки:** у середовищі внесення змін немає .NET SDK, тому `dotnet build` і `dotnet test` тут не запускалися. Додані C# тести потрібно виконати локально або в GitHub Actions. Python-перевірка еталонів не замінює компіляцію та запуск тестів самого C# проєкту.

Цей запис описує лише допомогу ШІ. Команді потрібно самостійно перевірити зміни, запустити .NET-тести та додати власний розподіл відповідальності й пояснення модулів, які кожен учасник зрозумів.
